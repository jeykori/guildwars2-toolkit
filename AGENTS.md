# AGENTS.md

Contributor and agent operational guide for `@jeykori/guildwars2-toolkit`. Consumer documentation lives in `README.md`.

## Overview & Architecture

`@jeykori/guildwars2-toolkit` is an ESM-only TypeScript library published to npm, providing Guild Wars 2 DPS report parsing, log aggregation, and React UI components. The package exposes three subpath exports: `@jeykori/guildwars2-toolkit/utils` (Node/Bun runtime data processing), `@jeykori/guildwars2-toolkit/types` (shared TypeScript definitions), and `@jeykori/guildwars2-toolkit/ui` (browser-targeted React 19 components). React, Recharts, and Tailwind CSS v4 are optional peer dependencies required only when consuming the `./ui` export.

## Directory Map

- `src/utils/`: Core backend data mappers, aggregators, calculation metrics, and encounter plugins (e.g., Cerus CM). Entry: `src/utils/index.ts`.
- `src/types/`: Shared TypeScript type definitions and interfaces. Entry: `src/types/index.ts`.
- `src/ui/`: React UI components, layouts (`DpsReportSummaryLayout`), and shadcn primitives (`src/ui/shadcn/`). Entry: `src/ui/index.ts`.
- `dist/`: Build output generated by `scripts/build.sh` (`dist/utils`, `dist/types`, `dist/ui`).
- `playground/`: Vite + React 19 test app for inspecting parser outputs (`/parse-dps-report`) and summary UI (`/dps-report-summary/:reportId`).
- `scripts/`: Build pipeline (`build.sh`) and data generator (`regenerate-data.ts`).
- `.github/`: GitHub workflows and automation (if configured).

## Conventions & Patterns

- **Runtime & Toolchain:** Bun for execution and package management (`bun`), TypeScript 5 with `"module": "Preserve"` and `"moduleResolution": "bundler"`.
- **Code Style & Formatting:** Biome (`biome.jsonc`, VS Code integration). Use tabs and follow recommended linter presets. Run `bun run check` to format and fix.
- **Strict Typing:** Strict null checks, `noUncheckedIndexedAccess`, and `verbatimModuleSyntax`. Avoid `any` in public exports and business logic.
- **Export Decoupling:** Keep `./utils` and `./types` strictly headless and decoupled from DOM/React dependencies. Never introduce UI peer dependencies into `./utils`.
- **Side Effects:** Maintain `"sideEffects": false` in `package.json` for tree-shaking. (Note: `scripts/build.sh` temporarily removes this field during `bun build` to work around a bundler issue, then restores it).
- **Path Aliases:** Library code uses `@/*` for `src/ui/shadcn/*`. In `playground/`, `@jeykori/guildwars2-toolkit/*` maps to `../src/*`.

## Validation Commands

Run all checks from repository root:

- **Type-Check All:** `bun run typecheck` (combines utils, ui, playground, and tests)
  - `bun run typecheck:utils`
  - `bun run typecheck:ui`
  - `bun run typecheck:playground`
  - `bun run typecheck:tests`
- **Lint & Format Check:** `bun run ci` (or `bun run check` to auto-fix)
- **Unit / Integration Tests:** `bun test`
- **Build Package:** `bun run build` (builds ESM bundles & generates `.d.ts` files into `dist/`)
- **Dev Playground:** `bun run dev` (starts Vite dev server in `playground`)
- **Regenerate Mock Data:** `bun run regen`

## Guardrails

- **Zero Secret Exposure:** Never read `.env*` files or print environment variables. Test API tokens and npm credentials belong solely in local untracked files or GitHub Actions secrets.
- **No Artifact Commits:** Never commit `dist/`, build caches, logs, or coverage outputs.
- **SemVer & Public API Integrity:** Do not introduce breaking changes to public exports (`./utils`, `./types`, `./ui`) without explicit semver consideration.
- **Documentation Sync:** When modifying public APIs, exports, peer dependencies, or playground dev routes, always keep consumer-facing instructions in `README.md` synchronized.
